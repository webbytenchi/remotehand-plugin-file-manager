# RemoteHand File Manager v0.1.0 Design

Status: **Implemented and accepted**

This document records the finalized v0.1.0 scope for RemoteHand File Manager.

The milestone establishes a reliable local-filesystem browser and file-operation foundation without attempting to replace the operating system's full desktop file manager.

## Product principles

- Local filesystem first.
- Windows-first implementation and acceptance testing.
- Preserve Windows + Linux portability in the design.
- Programmer/sysadmin-oriented behavior.
- Safe, predictable filesystem operations.
- Long-running work must not block the File Manager UI.
- RemoteHand core owns generic plugin infrastructure; File Manager owns file-management semantics.

## Layout and state

File Manager starts in single-pane mode and can switch to dual-pane mode.

The plugin persists:

- single-pane vs dual-pane preference
- left pane path
- right pane path
- active pane

Each pane maintains independent runtime navigation history and selection.

## Browser presentation

Each pane uses a details/table presentation with:

- Name
- Type
- Size
- Modified

Directories are presented before files with predictable case-insensitive name ordering.

Column sorting controls are deferred beyond v0.1.0.

## Navigation

Each pane supports:

- Back
- Forward
- Parent
- Refresh
- clickable breadcrumbs
- editable path input
- Alt+Left
- Alt+Right
- Alt+Up
- F5
- Ctrl+L
- mouse side-button Back/Forward

Double-clicking a directory, or a valid directory symlink, navigates into it.

Opening regular files with the operating system's default application is deferred.

## Selection

v0.1.0 supports desktop-style selection:

- click for a single item
- Ctrl+Click to toggle items
- Shift+Click for a range
- Ctrl+Shift+Click for an additive range
- Ctrl+A for all items

Copy, Cut, Delete, drag-and-drop, and dual-pane operations can act on multiple selected items.

Rename and Properties require exactly one selected item.

## File operations

v0.1.0 includes:

- New Folder
- Rename
- Copy
- Cut
- Paste
- Move
- Copy to Other Pane
- Move to Other Pane
- Delete to Recycle Bin / Trash
- Properties
- Copy Path
- Copy Filename

Copy Path and Copy Filename support multiple selected items by placing one value per line on the clipboard.

## Copy and Move job model

Copy and Move use a shared background job engine.

The job flow is:

1. validate the entire request
2. scan selected content
3. report discovered item and byte totals
4. perform Copy or Move
5. report progress
6. refresh File Manager panes on completion

The engine supports:

- single and multi-source jobs
- live scan totals
- byte progress
- item progress
- cancellation checks
- destination-conflict rejection
- recursive directory copy
- symlink preservation without recursively following links
- partial-copy cleanup on ordinary operation failure/cancellation

Only one operation is presented as active in the File Manager UI.

## Delete job model

Delete uses Recycle Bin / Trash behavior.

The flow is:

1. confirm the deletion
2. scan the selected content in the background
3. report discovered item and byte totals
4. allow cancellation while scanning
5. hand the selected items to the operating system Recycle Bin / Trash operation
6. disable cancellation once that operating-system operation begins
7. refresh the panes when complete

This avoids presenting unsafe or misleading cancellation semantics.

## Properties

Properties are read-only.

Files show immediately available metadata.

Folders start a separate cancellable background scan that reports:

- files
- folders
- links when present
- aggregate file size

The Properties scan is independent of Copy/Move/Delete jobs.

Dismissing the modal by Close, Escape, or clicking outside cancels an active folder scan.

## Internal drag-and-drop

Internal drag-and-drop is included in v0.1.0 after the Copy/Move job engine was accepted.

Supported destinations:

- the other pane's current directory
- a directory row
- a valid directory-symlink row

Dragging an already-selected item carries the existing selection. Dragging an unselected item first selects that item.

The drop target is highlighted.

After drop, the user explicitly chooses:

- Copy here
- Move here
- Cancel

The selected operation is executed by the same Copy/Move job engine as toolbar and context-menu operations.

External OS drag-and-drop is deferred.

## Context menu

Right-clicking an item opens the File Manager context menu.

The menu includes applicable actions such as:

- Copy
- Cut
- Rename
- Delete
- Properties
- Copy Path
- Copy Filename
- Copy to Other Pane
- Move to Other Pane

Right-clicking an unselected item first selects it. Right-clicking a member of an existing multi-selection preserves the selection.

The browser/WebView native context menu is suppressed outside editable text controls.

## Symlinks and special files

Symlinks are distinguished from normal entries.

Recursive operations do not blindly follow symlinks.

Directory symlinks can be navigated when their target is available.

Broken links remain visible and are treated conservatively.

Unsupported special filesystem entries fail safely.

## Persistence

v0.1.0 persists File Manager UI state through plugin-scoped storage.

Runtime Back/Forward history is maintained per pane but is not required to persist across full RemoteHand restarts.

## Deferred beyond v0.1.0

Not part of the finalized first release:

- external OS drag-and-drop
- directory tabs
- folder tree sidebar
- batch rename
- permanent delete
- archive create/extract
- checksums
- permission editing
- directory comparison
- rich previews
- recursive filesystem search/indexing
- cloud or remote filesystem providers
- Editor integration
- SFTP integration
- generic action/intent contracts not yet required by concrete integrations
- column sorting controls
- hidden-files toggle
- opening regular files with the OS default application

## Acceptance style

v0.1.0 was developed using:

- small purposeful commits
- automated regression tests for meaningful behaviors and discovered edge cases
- focused manual acceptance tests
- live observed behavior as the source of truth

The release should be tagged only after documentation, dependency lockfile, build/package output, and final repository state are verified.
